## Goal

A request names what it accepts with Accept, names its body with Content-Type, and arrives through the proxy. A request that lacks one is refused before the operation runs, and the answer names the header. These are recorded examples. Changing measurements and progress counters use labelled placeholders. Stream read boundaries are combined; progress shows representative first and last samples. Repeated working-task polls are shown once per task. Complete recordings and checks remain in internal evidence.

Category: API handling. This page has 7 step(s). 7 passed.

## Before you start

- The api address is `https://localhost:8443`.
- A bearer access token with the scopes read, write. The commands show `<YOUR_ACCESS_TOKEN>` where your token goes.

### HTTP: Create a book with every required header

Flag: **PASSED**

Where: POST /v1/publishers/acme/books?bookId=dune

Action: Call books.create to Create a book. Token scopes: read, write.

Expected result: The call succeeds.

Checks:

- PASSED: Outcome is success

Expected outcome: success

Actual outcome: success

Command:

```bash
curl --request POST 'https://localhost:8443/v1/publishers/acme/books?bookId=dune' \
  --header 'authorization: Bearer <YOUR_ACCESS_TOKEN>' \
  --header 'accept: application/json' \
  --header 'content-type: application/json' \
  --header 'x-platform-proxy: <proxy secret>' \
  --data '{"title":"Dune","author":"Frank Herbert","authorEmail":"frank@example.com"}'
```
